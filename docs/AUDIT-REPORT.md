## 2. Architecture

```
Legacy HTML ──extract──▶ content/raw ─┐
categories.json + corrections.json ───┼─▶ build-catalog ─▶ content/generated/catalog.json ─┐
legacy images ──download (.cache)─────┘        └─▶ image-jobs ─▶ optimize-images ─▶ public/images
                                                                                       │
app/ (Server Components, generateStaticParams) ◀──── lib/catalog, lib/seo, content/pages ┘
   └─▶ next build (output: export) ─▶ out/*.html ─▶ postbuild (_redirects, _headers) ─▶ Netlify CDN
```

Client JavaScript is limited to: header menus, mobile drawer, search dialog, product grid (filters/lightbox),
shortlist, quote form, gallery and video. The drawer, search, shortlist and lightbox are code-split and load on
first use.

## 7. Remaining issues and recommendations

- **Mobile performance headroom**: the floor is React/Next hydration (~66 KB framework chunk). Pages with many cards (Tiles, 93) hydrate the most. Further gains: paginate very large grids, or move cards to Server Components with a lighter client filter layer.
- **Content management**: products are edited in JSON + a build step. For non-developers, a headless CMS (Sanity/Decap) is the recommended next step.
- **Dev-dependency advisories**: `npm audit` reports 0 vulnerabilities in production dependencies; 10 moderate advisories are in dev tooling (transitive `minimatch`) and do not ship.
- **Analytics**: none was present on the legacy site. Add privacy-friendly analytics with events for calls, WhatsApp taps, shortlist and form submits to measure enquiry conversion.
